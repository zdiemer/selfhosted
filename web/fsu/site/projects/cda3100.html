Notes on Assignment 4

  • The first number is never checked for being negative. The count-is-zero path initialises the minimum and jumps straight to the arithmetic, skipping the sign test. So typing -1 to an empty program does nothing; it takes a second one. Measured: -4 2 -1 reports a sum of −2.
  • Max starts at zero and is never seeded. Min is initialised from the first value; max is just whatever $s3 held, which under spim is 0. All-negative input — reachable only through the bug above — reports Max is: 0.
  • It never returns to main. readInt is entered with jal, but the way out — through end, varianceLoop and printVariance — reloads $ra from the slot where main saved its return address. So the final jr $ra goes straight back to spim's startup code, as though main had returned, and main's own epilogue is dead code. On the way it releases 4 of main's 8 stack bytes and reloads $s0 from a slot nothing ever stored to. None of it reaches the output, which is presumably why it passed.
  • At end of input it never stops. spim's read_int returns 0 at EOF, forever, so the negative sentinel never arrives: the program keeps storing zeros, through its 100-word array and on past it, until spim starts raising “Bad address” exceptions at steadily climbing addresses — without end. The terminal disables Ctrl-D and caps output, so you cannot fall into it.
  • There is no bound on the array either. A 101st number is stored past the end of arrayInt. It is the last thing in .data, so in practice nothing is overwritten, and 1 to 101 still averages to 51.

Verilog

Neither testbench has a $display or a $finish. They were written to be looked at in ModelSim's waveform window, so a command-line simulator runs their free clock forever and prints nothing. The build compiles each file exactly as submitted alongside a small second top-level module that reads the testbench's wires by hierarchical reference, prints them, and stops — iverilog -s test_bench -s harness. The harnesses are in web/fsu/sims/.

Homework 8 · a Gray-code counter

Three D flip-flops and the next-state logic for the 3-bit Gray sequence 000, 001, 011, 010, 110, 111, 101, 100. The assignment sheet supplied the sequence; the equations are the student's. Source.

  • It is a race that happens to come out right. The flip-flop is always @(posedge clk) Q = D; — a blocking assignment. Three of them share one clock edge, and each one's D is computed from the others' Q. Whether a flop sees its neighbours' old value or new one is up to the simulator's scheduling. ModelSim in 2014 and Icarus 11 in 2026 both produce the correct sequence; the build asserts it, so a simulator that disagrees will say so.
