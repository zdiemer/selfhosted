MyDS

A separate-chaining hash table in C++, January 2015. The whole repository is two header files: no main(), no Makefile, no README, two commits, and nothing since.

A caveat about the course

I have seen this attributed to COP 4530, and the date and the naming convention fit — but nothing in the repository says so. There is no README, no header comment and no assignment text. Treat the course as a guess; the January 2015 date and the authorship are the only parts I can actually source.

What exists

MyHash.h is a functor wrapping djb2. MyDS.h is the table: a vector<list<string>>, an int max_size and an int size, all private, with exactly four public members — a constructor, a destructor, push and search. That is the entire surface.

It was written against an instructor's driver that was never committed, so from a clone it has never been runnable at all. The REPL on this page is a harness written in 2026; it lives outside the repository and the repository is untouched. It does reach into the private members — the bucket distribution and the rehash are the whole point of the assignment, and there are no accessors, not even size() — so every number it prints is read from the real object rather than reconstructed.

Notes, eleven years on

  • size does not count what you think it counts. push increments it only when a bucket goes from empty to non-empty, so it is a count of occupied buckets, not of elements. There is no accessor, so nothing outside the class could ever have noticed.
  • And then a rehash makes it wrong. rehash() builds a new vector, splices every chain into it and swaps — without recomputing size. The moment a rehash separates two keys that used to share a bucket, the real occupied count moves and the field does not. In the demo it ends up short by about 150, permanently, and nothing in the class ever corrects it. It is also the left-hand side of the growth condition.
  • The table starts with 60,000 buckets — roughly 1.5 MB of empty std::list headers — with the comment “to avoid expensive rehashing at larger sizes”. It works, but it also means the size == nodes.size() growth trigger needs 60,000 occupied buckets and can never realistically fire.
  • So the only reachable trigger is a chain of 150, and since push does not deduplicate, the way to reach it is to insert the same string 150 times. Which then cannot be fixed by rehashing, because identical keys hash identically — so every subsequent insert of that word quadruples max_size and rebuilds the entire table again. max_size *= 4 overflows a signed int after seven of those.
  • A miss can cost far more than a hit. search is std::find over the bucket's list. With 150 copies of one string in a bucket, finding it stops at the first node and failing to find something else in that same bucket walks all 150. The demo brute-forces a colliding key so you can watch both numbers.
  • There is no remove(). Not an oversight I can dress up — deletion was not part of the assignment and was never written. The REPL does not pretend otherwise.
  • The destructor sets max_size = 6000. A dropped zero, in code that runs immediately before the object ceases to exist. It is harmless, and it is how you know nobody ever read it.
  • The hash copies every key. MyHash::operator() takes its string by value, including inside rehash()'s inner loop. And s[i] is a plain char, which is signed on x86, so any byte above 0x7F sign-extends into the accumulator — invisible with ASCII words, which is all this was ever fed.

What -Wall -Wextra still says

Three warnings, all the same one: a signed loop counter or field compared against an unsigned size(). The REPL's warnings command prints them in full. Both headers otherwise compile clean at C++17 without a single change.
