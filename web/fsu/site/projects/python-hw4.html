Python Homework 4

Python Programming, April 2016. Two scrapers, 118 lines between them, in Python 2 — both of whose targets are gone.

Neither can run against the live web: the CS department's site has been redesigned since, and imgur's per-user comment feed no longer exists. So both ran once, during this site's image build, against a recording. The scripts are untouched; what stands between them and the network is a short replacement for requests (web/fsu/pyhw4/shim/) that answers only from files on disk, and refuses any URL it has no recording for.

faculty_directory.py

Fetches the department's faculty list, follows the first link in every row of table#faculty, and prints name, office, phone and email from each person's page — four XPath expressions, each in a bare try/except that prints N/A when it finds nothing. Source.

Its inputs here are Wayback Machine captures: the faculty list as of 26 March 2016, the last capture before the homework was handed in, and for each of the 32 links the 2016 XPath finds in it, the closest capture of that page. Most date from April 2016; a few pages were not crawled then and their nearest capture is as late as August 2017. They are fetched by the image build and never stored in the repository, which is public. They are fetched as the original bytes, not the Wayback's rewritten page with its toolbar, so the XPath written against the live site in 2016 still finds all 32 links in them. On this build it fills 121 of the 128 fields; the seven N/As — six phone numbers and one office — are pages where the 2016 XPath found nothing.

imgur_battle.py

Given several imgur usernames, it pages through each user's comments, finds the posts all of them commented on, sums each user's points on those posts, and names a winner. Source.

The data below is invented. The endpoint it read, /user/<name>/index/newest/page/<N>/hit.json, is gone and was never archived for arbitrary users, so there is nothing real to replay. Two placeholder users and four responses exist only to make the bug below happen; web/fsu/pyhw4/imgur/README walks through them.

Notes, ten years on

  • imgur_battle.py does nothing when run. It defines battle(*users) and never calls it. The build drives it with a two-line script that imports the module and calls it once.
  • It can name no winner at all. high_score is updated after every post, from running totals, and the winners are the users whose final total equals it. imgur comment points can be negative, so a running total can peak above where it ends: here alice reaches 10 on the first shared post and finishes on 4, nobody finishes on 10, and the program prints The winners are []!
  • Which post counts first is Python's choice. The shared posts are a set, so whether the bug shows depends on set iteration order. Python 2 makes that deterministic; Python 3.3+ randomises string hashing per process, so the same input would flip between a winner and no winner from run to run.
  • Paging stops only on an empty body. while page.text != '' — if the endpoint ever answered a page past the end with valid JSON and an empty list, rather than nothing, this would request pages forever. There is no way left to check which it did.
  • The email field has a fallback. If the first text node in the email cell is blank, it takes the second — a special case for at least one page the author must have seen in 2016.

Run with

Python 2.7.18 and lxml 4.9.4 — not the lxml of April 2016 (3.6.0), because 4.9.4 is the last release with a Python 2 wheel and the build installs offline. The script calls two XPath methods; both behave the same in each. PYTHONIOENCODING=utf-8 stands in for the UTF-8 terminal it was written in, without which Python 2 raises on the first non-ASCII name it prints to a pipe.
