Cloysta

A Unix shell in C. Florida State, Operating Systems, Fall 2015, written with Taylor Ereio — thirty commits, all of them on the night of 28 September, from linprog1 and linprog3 in the CS lab.

Checking…

A real PTY, a real fork/execv, running the binary gcc produced from the 2015 sources. Type exit to leave.

What it does

Source
github.com/zdiemer/Cloysta — roughly 1,500 lines of C across REPL/ and UTILS/.
Structure
Exactly the loop the assignment asked for: _setup → _prompt → _read → _parse → _execute, one file each.
Builtins
exit, cd, echo (with $VAR expansion), export, etime, limits. Everything else is resolved against PATH and execv'd.
Also implemented
> and < redirection via dup2, background jobs with &, and a hand-rolled allocation tracker in UTILS/memmy.c.
Dependencies
None. No readline, no ncurses — which is why there is no history and why the arrow keys just emit escape codes at you.

Notes, eleven years on

  • The shell cannot detect end of input. REPL/read.c calls fgets and throws the return value away, then returns line == NULL ? 0 : 1 — but line is the caller's buffer and is never null, so it always returns 1. The run = 0 branch in main.c that was supposed to handle EOF is unreachable code. At EOF fgets leaves its buffer untouched, so strcpy copies uninitialised heap and the shell reprints the prompt forever.
    Measured here: about 42 MB of prompt in 13 seconds. This session disables the terminal's EOF character outright so a stray Ctrl-D cannot reach that path, and caps CPU seconds in case anything else does.
  • export cannot outlive the line it was typed on. It calls putenv(args[1]), and args is main()'s char cmd[255][255] stack array. putenv stores the pointer rather than a copy, and _setup() zeroes that array at the top of every loop — so by the time you can type echo $FOO, the environment entry points at bytes that have been cleared. Try it; it says the variable is not found.
  • The pipe does not read your command. findPipe() prints “Warning: Piping does not work correctly” and calls mpipe(), which is hardcoded to /bin/ls | /bin/more — the real argument parsing is sitting right there, commented out. It also calls pipe() after forking rather than before, so the two halves get different pipes. The container ships more at that exact path purely so the failure is the interesting one rather than “command not found”.
  • cd builds its argument out of garbage. chgdir() declares char path[510];, never initialises it, and then strcats "PWD=" onto whatever was on the stack. It works when the stack happens to start with a zero byte. When it does not, the shell dies — which is why the session wrapper restarts it rather than pretending that does not happen.
  • Two commands fork a second shell. The child in compute_limits() never calls exit(); it returns up through _execute into while(run) shell_loop(...). A failed background execv does the same thing, because that branch has no exit(1) after it. Both leave a duplicate shell competing for your keystrokes.
  • The makefile never built this. It sets C=gcc and then every rule uses $(CC), so it silently fell back to make's built-in cc; one rule depends on an object file it has no recipe for, which is why a stale echo.o is committed to the repository. And -std=c99 -D_XOPEN_SOURCE hides the declarations of putenv, gettimeofday and MAXPATHLEN that the code calls anyway — harmless in 2015, an error on a modern compiler. It is built here with -std=gnu99, at -O0 so that eleven years of optimiser improvements do not quietly change what all that undefined behaviour does.

The container it runs in

This program resolves a name against PATH and execvs it, so the container is the security boundary rather than the shell. It holds no credentials and no Kubernetes token, its root filesystem is read-only, and its network policy denies all egress — there is no DNS, so ping and curl hang rather than failing quickly. The command set on PATH is a deliberately short list of the boring ones. Each session is capped in wall-clock seconds and, separately, in CPU seconds, because an idle shell and a runaway one look identical to a clock.
