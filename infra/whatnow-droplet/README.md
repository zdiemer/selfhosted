# Whatnow production droplet

This directory owns the production host configuration. The application repo owns
application code and image builds; its old `deploy/provision.sh`, `cf-firewall.sh`
and manual `.env` instructions are superseded here.

## Apply desired state

Prerequisites: `uv`, Python 3 with PyYAML, 1Password CLI access to the `homelab`
vault, and SSH alias `whatnow` with root access. The shared `op-session.sh` helper
obtains the existing vault session. SSH host-key checking remains enabled.

```sh
infra/whatnow-droplet/apply.sh --check --diff  # drift preview on a managed host
infra/whatnow-droplet/apply.sh                # apply and check site health
```

Ansible Core is pinned by the wrapper. `inventory.yml` selects the host;
`config.yml` pins application and Caddy versions, interfaces and Cloudflare CIDRs.
To release or roll back, change `whatnow_tag`, commit, then apply. Images are pulled
before the runtime environment changes. The application image version is never
read from a mutable `latest` tag or the secret file. Changes to runtime config
recreate containers so bind-mounted Caddy files cannot retain an old inode.

The playbook manages Docker installation (Ubuntu 24.04 amd64), Compose, Caddy,
registry authentication, application environment, bounded logs, cache maintenance,
and the persistent origin firewall. It preserves application data and TLS volumes.
Container health and public HTTPS must pass before an apply succeeds. A second
unchanged apply should report zero changes. Package upgrades and host reboots are
separate maintenance operations.

## Secrets

The **1Password `homelab/whatnow-production` item** is the source of truth:

- `app.env`: production dotenv configuration, including the existing session
  secret, password pepper and provider credentials. Do not add `WHATNOW_TAG`.
- `docker.json`: Docker authentication containing only the GHCR pull credential.
  Use a dedicated `read:packages` credential.

Edit these fields in 1Password, then run `apply.sh`. Do not edit the droplet.
The password pepper must be preserved: changing it invalidates existing password
hashes. Session-secret rotation invalidates sessions. Neither is regenerated by
this playbook.

The one-time adoption imported the existing environment and registry credential
without exposing values and verified their vault round trip. `import-existing.py`
is the adoption helper; it refuses to overwrite an existing vault item. It needs
an authenticated `op` session, and captures SSH output in process memory only.

The wrapper fetches secrets into a private tmpfs directory and cleans up on exit.
Ansible stages transfers under `/run` remotely, suppresses secret task output and
diffs, and writes root-owned mode-0600 files on the droplet. Runtime `.env` and
Docker credentials **still exist on the droplet's disk**, and Docker environment
values are visible to root. This is centralized secret management, not protection
against host-root compromise. Whole-disk backups contain those files too. No vault
access credential is installed on the droplet.

## Origin firewall

`whatnow_origin` is an isolated nftables table. Its prerouting hook runs before
Docker DNAT, so both Docker-published ports and host listeners are covered. On
`eth0` and `eth1`, TCP 80/443 admits only Cloudflare IPv4/IPv6 ranges. UDP 443 is
closed; Cloudflare uses TCP to this origin. SSH and other services are unaffected.
Existing Docker and UFW rules are not flushed. UFW admits SSH and web service
ports; the earlier nftables hook is the authoritative Cloudflare source filter.
This avoids stale UFW source ranges blocking a future Cloudflare range update.

The table is replaced in one nftables transaction, after syntax validation.
A systemd unit loads it at boot; Docker requires that unit before starting.
Every apply also reconciles runtime rules. No firewall restart is required for
range updates, and the same CIDRs generate Caddy's trusted-proxy configuration.
Review `https://www.cloudflare.com/ips-v4` and `/ips-v6` when updating ranges;
commit changes to `config.yml`, then apply. Failed downloads never empty the live
allowlist because deploy does not fetch its firewall inputs dynamically.

Verify from outside Cloudflare:

```sh
curl --noproxy '*' --connect-timeout 5 --max-time 8 \
  --resolve whatnow.gg:443:64.227.0.147 https://whatnow.gg/healthz
# Must fail to connect/time out; it must not return HTTP 200.
curl -fsS https://whatnow.gg/healthz
# Must succeed through Cloudflare.
```

Keep Cloudflare proxying enabled and TLS in Full (strict) mode. Caddy's existing
HTTP ACME challenge must remain reachable through Cloudflare; do not add an edge
rule that blocks `/.well-known/acme-challenge/`. Restricting source ranges does not
prove a request belongs to your Cloudflare zone: authenticated origin pulls or a
tunnel would be a separate, stronger identity control.

## Recovery and scope

For a replacement Ubuntu 24.04 amd64 droplet: install the SSH key, update the SSH
alias/inventory, restore the data and Caddy volumes from backup, verify interface
names, then apply. Preserve the vault item. Point Cloudflare at the replacement
origin. The initial apply needs SSH and Python; an initial `--check` cannot fully
simulate services/directories that do not exist yet.

Droplet creation, DigitalOcean backup scheduling, DNS and Cloudflare account
settings are not managed by this host playbook. No provider API credentials were
needed for adoption. This does not claim a whole-account Terraform migration.

For recovery from a bad CIDR change, SSH remains available: correct `config.yml`
and apply. Reverting the Git config and applying rolls back managed settings.
Do not flush the entire nftables ruleset. A reboot test should be done in a
maintenance window; normal verification checks unit dependencies and reloads the
firewall without restarting Docker or rebooting the host.
